# Architecture

CertiTrack is a static web app (no build step) on Netlify, backed by Supabase
(Postgres + Auth + Storage + one Edge Function).

## The model: a network of equal peers

- **Organizations** sign up (one owner account each) and upload **certificates**
  (PDF + metadata, versioned).
- Two organizations **connect** (request → accept). Once active, the connection
  is symmetric: neither side has more rights, and either side can end it.
- Each certificate has a **sharing** mode:
  - `private` — only the owner's members,
  - `all_connections` — every organization the owner is actively connected to,
  - `selected` — only organizations listed in `certificate_shares`, each with an
    optional expiry date.
- Access is **never transitive**: if A↔B and B↔C, A sees nothing of C and
  cannot learn that B and C are connected.
- Either side can **request a document type** from the other
  (`document_requests`). A request is fulfilled automatically as soon as a
  matching certificate becomes visible to the requester; the requester is then
  warned before it expires and told when it is renewed.
- Partner **views** of PDFs are logged (`certificate_views`). Storage serves a
  partner a PDF only right after `ct_open_certificate` logged the view.
- **Platform admins** (`platform_admins`) see everything, including the whole
  network (`ct_admin_network`).

The single rule that decides partner visibility lives in one SQL function,
`ct_org_can_view_certificate(viewer, certificate)`, used by RLS on
`certificates`, `certificate_files` and `storage.objects`.

## Database

One baseline migration: `supabase/migrations/20261113000000_peer_network_baseline.sql`.
New changes go in new, timestamped migration files; never edit an applied one.

- Writes that involve more than one organization go through `SECURITY DEFINER`
  functions (`ct_*`). Clients get explicit **column-level** grants only for
  fields they may edit directly (organization profile, certificate metadata,
  notification preferences).
- Internal helpers (`ct_notify_org`, `ct_write_audit`, …) and scheduled jobs are
  not executable by clients. The helpers RLS policies call (`ct_is_org_member`,
  `ct_org_can_view_certificate`, …) live in the `private` schema, which the REST
  API does not expose, so nobody can probe e.g. whether two other
  organizations are connected.
- Audit triggers record every change to core tables in `audit_log`.

Tests: `npm run test:db` applies the migrations to a throwaway local Postgres
(with a small stand-in for Supabase's `auth`/`storage` schemas,
`supabase/tests/00_supabase_stub.sql`) and runs `supabase/tests/10_peer_network_test.sql`
— 64 assertions on privacy and the peer model. CI runs it on every push.

## Frontend

All of it is TypeScript, type-checked strictly (`npm run typecheck`).

```
index.html, pages/**.html   HTML shells (generated by scripts/build-pages.mts), Vite entry points
src/app/main.ts             entry of every signed-in page: checks the session, draws the shell
src/app/shell.ts            top bar, side menu, notifications, account menu
src/app/router.ts           moves between signed-in pages without reloading (see below)
src/app/page.ts             PageDef / PageContext: what a signed-in page is
src/pages/<area>/<page>.ts  one module per page (organization/, admin/: a PageDef; auth/, public/: standalone)
src/api/index.ts            the data API the pages use (Api interface in src/types/domain.ts)
  supabase.ts               real backend
  demo.ts                   in-browser copy of a network for the demo (same API, same sharing rules)
src/types/                  database.ts (generated from the schema), domain.ts
src/ui/                     chrome (theme, language, brand), dialogs, components, icons, password field
src/lib/                    html templating (auto-escaping), formatting, i18n, form helpers
src/i18n/{el,en}.ts         translations (the English dictionary must have exactly the Greek keys)
src/styles/app.css          the design system (tokens, light/dark, mobile-first)
```

- **No reloads inside the app.** Every organization and admin page loads the
  same entry (`src/app/main.ts`). The router intercepts menu clicks and links to
  pages of the same area, loads that page's module, lets it build its content
  off-screen and swaps the main area in one step. The previous page stays on
  screen until the next one is ready (a thin bar shows progress); only a page
  slower than 1.5 s shows a spinner. Back/forward and direct links work as usual.
- All markup is built with the `html` tagged template, which escapes every
  interpolated value unless explicitly wrapped in `raw()`.
- The demo runs the real pages against `src/api/demo.ts`; nothing leaves the
  browser. On the real site only a platform administrator can start it (menu
  item "Demo"); development and test builds (`VITE_ENABLE_DEMO=true`) open it to anyone.
- Icons are a generated subset of Lucide (`node scripts/build-icons.mts <lucide package>`).

## Background work

`supabase/functions/process-notifications` runs on a pg_cron schedule. It calls
`ct_generate_expiry_notifications()` (own and partner expiry reminders) and
sends queued rows of `email_outbox` over SMTP. Email titles and bodies come from
the database, so in-app and email notifications always match.

`netlify/functions/finalize_account_erasure.mts` is the platform-admin tool that
deletes a closed organization's PDFs and personal data (GDPR erasure).
